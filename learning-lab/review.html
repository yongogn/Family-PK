Quest PK · Code, questions & learning review · 13 November 2026

Make learning the adventure.
Let arcade play be the reward.

The app has a useful foundation: seven subjects, procedural questions, explanations, family challenges, read-aloud support, and local progress. Its next priority should be trustworthy learning progression and a rewarding lesson loop, supported by the visual quality already being explored.

What was checked

Inspected the question banks, generators, adaptive-level code, star and token rewards, stage unlocks, Boss scoring, quiz callbacks, storage and backup code. Ran 1,200 generated cases per subject for preschool, school-level and adult routes: 7 × 3 × 1,200 = 25,200.

In this sample, generated choices had no blank or duplicate options and exactly one choice matching the stored answer. No generation exceptions occurred. Some younger questions intentionally use three options. This is a structural check, not validation that every factual answer, explanation, distractor or curriculum placement is correct. Spelling-builder and spoken-response workflows need their own checks.

Live learning rules and profile data have not been changed as part of this review. The accompanying prototype is a separate, session-only demonstration.

Fix these first

Confirmed · reward policy

1. Arcade access does not currently depend only on the star target.

arcadeOpen() allows access after 15 lifetime stars or a 10-answer streak. The visible parent “unlock all” button also bypasses progression without an adult gate. Once unlocked, the arcade stays unlocked and uses tokens, rather than requiring a fresh star target for each round.

Reproduced: a profile with 0 stars and a best streak of 10 has arcade access.

Recommendation: The confirmed direction is a fresh star target for every arcade round. Use a parent-configurable X newly earned learning stars per bounded arcade pass, preserve lifetime learning stars separately, and put overrides behind an adult gate. The live token system needs an explicit migration before this policy is adopted.

Source: arcade eligibility

Confirmed · rewards & reporting

2. A mastered level can mint tokens and “stars today” repeatedly.

The level’s stored best stars update only when improved, but every completion adds its full star result to tokens and daily star tracking. Tests also grant two tokens on completion, regardless of the result. Repeated practice can deserve recognition, but these credits currently do not distinguish learning something new, improving mastery, or repeating an already mastered task.

Reproduced: replaying a three-star level changed tokens from 3 to 6 while total stored stars stayed at 3.

Recommendation: award new mastery stars only for new or improved milestones. Give smaller, capped practice credits for useful review and effort. Make all reward grants idempotent so reopening a result or repeating an event cannot pay twice.

Source: level completion

Confirmed · scoring bug

3. A Boss answer can score multiple times.

Correct Boss answers schedule the next question after 250 ms, but do not immediately lock the current question. Repeated taps can move the rope multiple times for one answer.

Reproduced: two immediate calls on the same correct answer counted two correct answers and two rope pulls for one question.

Recommendation: lock the answer before applying any score change; identify the match and question in every callback. Apply the same protection to remote answers and freeze/unfreeze events.

Source: Boss answer handler

Confirmed · session bug

4. An exited quiz can reopen itself.

The correct-answer auto-advance checks a question token but leaving the quiz does not invalidate the quiz session. A pending callback can replace the map with another question after the learner exits.

Reproduced: the map was visible immediately after exit; three seconds later it had been replaced by a question card.

Recommendation: give every quiz a session ID, cancel scheduled work on exit, and bind it to its learner. Invalidate speech, feedback, spelling and Boss callbacks as part of the same lifecycle. Let learners manually continue after explanations, or make auto-advance a preference.

Source: answer and feedback flow

Confirmed · assessment claims

5. “Learning age” and “brain age” have no demonstrated calibration.

Child subject age is calculated as ability + 5. Adult brain age uses actual age + (7.8 − ability) × 9. A 12-question adaptive quiz and those formulas do not establish an age-equivalent score or a comparison with typical adults. A disclaimer does not validate the measurement.

Recommendation: show “working on Year 3 place value,” skill confidence, independent accuracy, and growth over time. Use curriculum labels only where the content is actually mapped and reviewed. Stop using age comparisons as the main success message.

Source: age calculations

Make learning more than a themed quiz

Learning design

6. Chapters need real learning objectives and mastery checks.

Chapter and node names mostly theme the experience; question selection is primarily subject + numeric difficulty. The code does not maintain a skill model for, for example, regrouping, inference, fractions or subject-verb agreement. Spelling peeks are counted in the temporary spelling state, but the answer log does not distinguish assisted answers from independent success. Four correct answers out of eight unlock the next level. With four equally likely choices, random guessing has roughly an 11.4% chance of reaching that threshold.

Recommendation: define a skill graph with prerequisites. Each short quest should teach one objective, offer guided practice, ask fresh independent checks, and record hint use and misconceptions. Boss challenges should review the chapter’s skills with balanced difficulty, rather than mainly reward speed.

Retention

7. Wrong answers should shape what happens next.

The app shows explanations and can display the current session’s review, but does not persist a structured learner misconception queue or a spaced-review schedule. Recent-question avoidance is not the same thing as deliberate spaced practice.

Recommendation: save skill and misconception IDs for errors, retry with a fresh equivalent problem, and schedule retrieval a day and several days later. Reward useful recovery and independent improvement. Let explanations remain on screen long enough to read.

Motivation across ages

8. Give learning the best progression, visuals and feedback.

Use the polished world as a learning map: each landmark represents a real skill, discoveries change the environment, and new learning earns visible progress. Keep the arcade smaller in the navigation. A child, teenager and adult should share a coherent world but get suitable tone, examples and challenge.

Recommendation: prioritise interactive learning tools—place-value blocks, number lines, sentence assembly, labelled diagrams, maps and prediction experiments. Keep decorative animation away from reading and answer controls. Recognise thoughtful reasoning rather than encouraging speed as the default.

Code structure and reliability

The implementation is one large HTML document with embedded fonts, styling, banks, state, learning logic, avatars, networking and arcade engines. Seven function names are declared more than once, including genQ, genBank, genMaths and avatar functions. Later overrides make it difficult to see which behaviour is active.

  • Split content, assessment, rewards, storage, quiz sessions, UI and arcade into small modules with documented interfaces.
  • Put questions in validated data files with stable IDs and reviewed sources. Keep generated-question tests separate from factual content review.
  • Centralise reward grants in one ledger; tests should assert that grants cannot duplicate and arcade eligibility follows the chosen policy.
  • Validate restored progress before replacing current state. Add a schema version, migrations, and visible handling of failed saves.
  • Scope service-worker cache cleanup: both existing workers currently delete every other cache on their origin. The Quest PK worker also treats every HTML navigation as the app entry page, which can overwrite its offline entry with an unrelated page. The preview is outside that worker’s scope.
  • Add regression coverage for learner switching, rapid taps, session exit, offline restore, question generation, progression and rewards.

Recommended delivery order

  1. Stabilise the core: fix duplicate scoring and stale sessions, validate rewards, correct confirmed question errors, and remove unsupported age claims.
  2. Agree the learning and reward rules: curriculum/locale, skill mastery, what earns a star, whether review earns separate credit, and the value of X stars per bounded arcade round. The per-round earning requirement is confirmed.
  3. Finish one polished learning slice: teach → guided practice → independent check → feedback → earned reward. This prototype demonstrates that direction.
  4. Extend reviewed skill coverage: expand subject by subject, with spaced review and meaningful parent summaries.
  5. Then improve arcade breadth: make a small number of high-quality reward games, while keeping the learning journey the main attraction.
